# 跨市场选线（同一公司多条上市线）

> 口径出处：`references/ah-overlay.md` 与 `references/adr-hk-overlay.md`，逐字取自上游
> [Howard-Jerry/quant-agent-skills](https://github.com/Howard-Jerry/quant-agent-skills)
> （MIT，commit `03677d2`）。那颗快照的三颗正文是自述的编排器、不进可选清单，随包只带这两份
> 零执行面的口径文件；为什么这么切、改了什么，见本快照根的 `UPSTREAM.md`。

## 什么时候用，什么时候不用

用：公司结论已经有了（或本次不打算重做），剩下的问题是**这次动哪一条线**——A 股还是 H 股、
ADR 还是港股、已持有的那条线要不要换成另一条。

不用：只有一条上市线的公司；比较两家不同公司；问"这家公司值不值得研究"。那些是本插件
其他研究路径的事，这颗一行都不接。**它不重做公司研究，只做选线。**

## 一条铁律

**公司层面只研究一次。** A 与 H、ADR 与港股，是同一家公司的两条线：现金流、竞争力、资产负债表
**完全相同**，不同的只有执行、价差、税、流动性、货币和你能不能买到。

由此得到两条禁止：

- **不得因为一条线更便宜，就上调公司层面的结论。** 折价是选线理由，不是"这家公司更值得拥有"的理由。
- **不得让包装层的便宜，盖掉公司层面缺失的证据。** 公司研究没做完，就先没有选线可言。

这两句是这颗的核心，其余都是把它们变成可检查动作的细节。

## 要拿的东西（一律走委派，本插件从不让分析角色自己伸手取数）

向宿主的数据面要，一次把三项写全，缺哪一项就点名哪一项并停止依赖它的判断：

1. **两条线在同一 as-of 交易日的收盘价**。币种分开写清楚：A 股那条是人民币，港股那条是港元，
   ADR 是美元。**不许拿实时快照与历史收盘混算**——溢价是"同一天两个价格的比"。
2. **同一天的汇率**（CNY 每 HKD，或 USD 每 HKD，按你对比的两条线取）。汇率取不到就是取不到：
   本插件的汇率条目按次消耗上游积分，凭据缺失、限流或后端报错一律不重试，也不许用记忆里的
   "大概 0.92"补一个数进去。
3. **窗口是否干净**：两条线各自最近的拆股、送转、供股、大股东减持、回购注销有没有落在
   你取的那段价格里。任一窗口被公司行动污染，就换到干净的后续窗口再比。

股息代扣税、通道可用性（港股通 / 直接开户 / 券商能不能买）这类**规则性**事实会改，
不向数据面要，按 `capital-web-protocol` 委派检索通道，把要核的问题、现行规则和时点写进 brief。

## 溢价怎么算

把算式写进答复里，让读者能复核——不要只给一个百分比。

```text
A/H 溢价 = (A_price_cny / fx_cny_per_hkd) / h_price_hkd - 1
ADR/HK 平价 = (adr_price_usd / adr_ratio) / (hk_price_hkd * fx_hkd_per_usd) - 1
```

- `fx_cny_per_hkd` 是**一港元合多少人民币**，方向写反等于把溢价倒过来。
- ADR 那条必须先除以 `adr_ratio`（一份 ADR 对应几股普通股），比例随公司行动变过就要重新确认。
- 两个式子用的都必须是同一个 as-of 日的收盘与同一天汇率；日期不一致就分别标注并说明差距有多大。
- 派生算术量大就交给宿主数据侧（委派 `data_junior`），少量数字在答复里把算式摊开即可。
  本插件的分析角色不自己跑脚本。

## 输出形状

```text
公司结论：<沿用已完成的那次研究，不在这里重做>
若触发行动，优先哪条线：<A / H / ADR / 不换>
理由：<价差 / 币种与股息税 / 流动性 / 通道 / 披露路径>，各一句
```

三份理由各归各位，不许混成一段"综合来看"。**价差只是其中一条**：一条线折价 30% 但你的账户
买不到，那它对这个人没有意义；港股通额度、停牌规则、涨跌停（A 侧有、港侧无）都属于通道与执行。

## 各市场要单独看的点

- **A/H**：A 侧有涨跌停与 T+1，H 侧没有；H 侧还要看港股通通道与股息代扣。具体口径见
  `references/ah-overlay.md`。
- **ADR/HK**：ADR 是**存托凭证不是股票**——要看换算比例、能不能跨市场转托管（fungibility）、
  退市与监管风险、以及**披露文件路径不同**：美国本土公司走 `10-K/10-Q/8-K`，外国私人发行人走
  `20-F/6-K`。一条线的公告在另一条线的检索面里可能根本不存在，这是**市场边界，不是数据缺口**；
  别把"这条线查不到"写成"这家公司没披露"。具体见 `references/adr-hk-overlay.md`。

## 出处块

分析结束时按本插件的统一形状交代出处，把每一项证据的来路写全：

```text
Data & Sources
  - <事实或数字>：来源=<Dataset 引用 / 披露文件名 / 网页标题与日期>
    as-of=<YYYY-MM-DD>
    Retrieval:  <delegated retrieval | web/tool retrieval | pasted by user>
```

`Retrieval` 只能是这三档之一。**"我记得大概是这个汇率"不是一档取数途径。**

## 这颗做不到什么（先说清楚，别到时候编）

- **本插件没有使用者的成交账本。** 这颗不持久化你的持仓、成本价与已实现盈亏。上文"已持有
  的那条线要不要换"只能按你在对话里当场给出的信息回答，回答完就放下；也不要假装查过账户。
- **没有现成的 A/H 溢价或 ADR 平价条目。** 溢价必须自己按两条线的收盘与当日汇率算出来，
  这三项里任何一项取不到，就不要给溢价数字，只报告缺哪一项。
- **不承诺收益，不预测价差收敛。** "A 比 H 贵 40%"是当天的事实，"所以 H 会涨"不是这颗的结论。
  历史价差区间可以作为参照，但要写明它是参照、不是目标。
- **不构成投资建议，也不代使用者下单。** 本插件不提供交易执行界面；最终动哪条线、动多少，
  由使用者自己决定并自己执行。
