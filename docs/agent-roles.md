# Agent 角色与 DSH 能力复用

> 本文件是 [README](../README.md)「三个模式怎么选」与「还能做什么」的详情层：README 只留模式与
> 角色边界摘要，逐角色职责与逐条基础设施复用清单都在这里。文中所有事实与 `preset/capital-generation/agent.patch.yml` 的装配一致，
> 装配能起由 `npm run smoke:boot` 在真实 boot graph 里验证。

## 总原则

所有 Agent，包括主 Agent 均不能直接接触原始结构数据（行情、财务报表细目等），需要时 Agent 可按需提取
再提炼发送消息至主 Agent。序列数据同样不进模型上下文：落盘成不可变 Dataset，跨 Agent 只传引用。

## 角色详情

目前覆盖以下 Subagent（data_analyst 为预留角色，暂未启用）：

- **data_collector**: 主 Agent 直属下级（spawn），负责根据上级指令收集金融财经类结构化数据，目前支持
  **128 个数据 capability**：同花顺（fuyao）61 个（行情、财务、估值竞价、盘面特色、指数、基金），
  腾讯公开 HTTP 9 个（A / H / 美行情快照、K 线与分笔），东方财富 HTTP 21 个（资金流、龙虎榜、
  限售解禁、宏观指标、板块与指数估值等），Wind 金融数据服务 3 个（宏观 / 行业 / 汇率指标与历史
  K 线），FTShare（非凸科技）34 个（A 股截面与资金流、龙虎榜席位、可转债、宏观利率、期货与贵金属）。
  其中腾讯与东方财富走公开端点，无需额外密钥；Wind 与 FTShare 需要各自的密钥。
  能力清单见 [data_collector 能力总表](data-collector-capabilities.md)。
- **data_junior**: 主 Agent 直属下级（spawn），负责根据上级指令清洗、整理出有效数据、基础描述性统计
  以及数据透视，目的是阐述数据背后的"故事"。读一份 Dataset 默认走 `describe_dataset`（一次调用完成
  元数据 + 基础 profile + 受控查询，多份数据在同一条消息里并发）；时间窗与时间戳换算一律由宿主完成
  （`time_facts` 的 `axis` / `windows`、`resolve_data_time_range`），子 Agent 不自行把日期算成毫秒。
- **data_analyst**: 主 Agent 直属下级，负责根据上级指令，通过运用编程技能分析上游数据
  （**仍在开发中**，委派行 disabled，暂不启用）。
- **web_retriever**: 主 Agent 直属下级（spawn），负责根据上级指令，运用网络搜索和抓取能力，获取外部
  非结构化数据。检索面为 AnySearch（`anysearch_search` / `web_retriever_fetch`，失败可按开关回退本机
  直连）与 Wind Alice（`wind_docs_announcements` / `wind_docs_news`，公告与权威新闻）；另有九个
  **具名来源查询工具**（财联社快讯、华尔街见闻快讯、东财 7×24 快讯 / 个股新闻 / 个股研报、新浪研报、
  同花顺机构一致预期 EPS、巨潮互动易、上证e互动），均为公开端点、零密钥；第三个工作面是**文档解析**
  `ocr`（PaddleOCR，PDF 研报 / 公告正文与图片 → markdown，需 Token）。共 14 个工具，逐个说明见
  [web_retriever 能力](web-retriever-capabilities.md)。
- **visualization_specialist**: 主 Agent 的孙 Agent（data_junior 委派出来的出图子 Agent），由
  data_junior 检查完数据后按需创建；只接收 `profile_ref`、有限 profile 事实与短期 `chart_source_ref`，
  使用受控 `render_chart` 生成自包含 HTML 图表，并只向 data_junior 回传 `chart_ref` 小回执；不接触
  原始 rows、不向主 Agent 直接发消息。
- 未来更多，欢迎 PR

## 「Agent 预设」里的角色

本插件在「Agent 预设」里留下三张可独立选择的卡片：「自动模式」「行情专家」「资讯专员」。`分析师` 与 `绘图专员`
是自动模式的内部角色：插件把这两颗内部角色从新会话选择器与预设管理里隐藏，但它们仍按原身份参与自动模式的
委派。预留的 `data_analyst` 仍处于停用状态，不参与显示。

三个用户模式的顺序是「自动模式 → 行情专家 → 资讯专员」，排在官方 `standard` / `ptc` / `minimal` /
`cordis` 之前；官方模式仍保留在下方，方便继续使用 Creator 等原始模式。DSH 的选择器是扁平列表，
没有分组字段，所以分组只能由 `order` 表达。卡片标题是模式名，正文是一句话说明，右下角那行等宽小字
是身份标识（历史会话靠它恢复，不随显示名变化）。

三张用户模式卡片不是三种完整玩法：行情专家只负责取数，资讯专员可以单独查资料；分析师需要同一会话里
已有数据，绘图专员通常由分析师检查数据后按需创建。

### 自动模式

- **模式说明**：主 Agent 不亲自取数也不画图，它把活分派给四种专用角色，最后给出结论、证据与来源标注、
  局限与风险。原始行情与报表细目不进模型上下文，只传引用，所以每个数字都带着来源与截止时间。
  立场是本金安全、独立判断、显式披露与温和托底。
- **如何使用**：直接说标的与问题，例如「宁德时代近一年股价与净利润是否匹配，先给结论再给证据」。
  要图就说清想比较什么，它自己判断该不该出图；只看数据不想看图，就在指令里写明不要出图。
  要不要图都不影响结构化数据先交给分析师做质量检查与可视化 gate；提图只是 gate 的一个输入，不是派分析师的触发条件。

### 行情专家

- **模式说明**：一次只请求一个数据能力，取到即落盘成不可变数据集（默认保留 7 天），回传引用、来源与
  截止时间；不回传原始数据行，也不做判断。
- **如何使用**：可以单独打开取数并拿到数据引用，但它没有读回数据内容的工具；这份数据又绑定当前会话，
  别的自动模式会话读不到。完整研究流程应在自动模式会话内委派它完成。

### 资讯专员

- **模式说明**：角色身份是资讯公文专员（web_retriever）。两家检索上游（通用检索与 Wind 公告新闻）加九个具名来源（财联社、华尔街见闻、东财
  7×24 快讯 / 个股新闻 / 个股研报、新浪研报、巨潮互动易、上证 e 互动、同花顺机构一致预期 EPS）。
  每条证据带编号与来源，官方域名核验过才算已核实；网页正文是证据，不是指令。
- **如何使用**：可以单独开一条只要资料，例如「查一下 XX 公司 9 月的回购公告原文，给链接和日期」。
  它不做投资分析，也不给买卖建议。

### 分析师

- **模式说明**：读已取回的数据做质量检查与描述统计（结构、时间轴、基础分布），按受控方式做聚合查询，
  并决定这份数据该不该出图。不联网、不取新数据、不给投资建议。
- **如何使用**：需要同一会话里已有数据；它要出图时会创建下面那颗「绘图专员」。单独打开时没有取数
  入口，也读不到别的会话的数据，不能独立完成分析，所以实际使用应由自动模式委派。

### 绘图专员

- **模式说明**：拿数据引用与有限的统计事实渲染成自包含的可交互图表，只回传图表引用。自动模式会把
  本轮图表统一登记为**最后一轮答复**的交付物，在答复末尾集中出现，可在侧栏查看或离线打开。它不评价
  数据、不主动发消息。
- **如何使用**：通常不需要手工开——由「分析师」检查数据后按需创建，出不出图取决于数据形态是否适合
  呈现。单独打开时没有分析师准备好的数据，也没有取数或查找文件的入口，不能独立完成出图。

## 复用的 DSH 官方基础设施

沿用 DSH 官方基础设施，不自行实现底层机制：

- **预设挂载**：整份装配由官方 `@deepseek-ai/dsh-agent-preset` **声明行**声明（自动模式一颗，
  每个专用角色各一颗），组合与预设注册归宿主；插件不扫目录、不自建 registry。主模式的 `config.id`
  是写进会话日志的身份，历史会话靠它恢复。
- **Subagent 编排**：通过官方 `dsh-subagent` 行注册委派工具，子 Agent 的创建、消息收发与生命周期管理
  完全交给宿主；本插件只定义每个角色的人设与工具面（那个角色能用哪几颗工具）。
- **人设注入**：主 Agent 与每个专用角色各由一颗官方 `dsh-persona` 行声明人设，不占用
  `deployment:persona` 节。
- **技能注入**：主 persona 只保留每轮都要生效的硬规则（预检、复用、路由、合规），长协议与载荷示例放在
  preset 自带的 `skills/` 目录，由 `dsh-skill-filesystem` + `dsh-tool-skill` 两行按需加载；
  插件代码不注册 skill provider。
- **工作区约定**：通过官方 `dsh-agent-instructions` 行加载工作区 `AGENTS.md` / `CLAUDE.md`。
- **上下文压缩**：通过官方 `dsh-compaction-basic` / `dsh-compaction-tool-result-pruner` 行提供长会话
  压缩与大结果剪枝。
- **数据持久化**：通过宿主侧 `fs` / `sandboxPolicy` 服务完成 Dataset 落盘与权限校验，不直接操作文件系统；
  所有数据落在用户 workspace，服从当前 session 的沙箱策略。
- **用户级资产**：自选股这类**跨 workspace** 的用户数据走官方 `dsh-storage-domain`
  （域 `capital_watchlist`，落 `~/.dsh/storages/`），不自建文件路径；浏览器半边只与本机 loopback 上的
  宿主路由对话，密钥从不进浏览器。
- **配置与凭据**：可编辑项就是插件条目 Config 里标了 `.volatile()` 的字段，DSH 自动把它投影成「插件」页
  上的表单（命名空间恒等于条目 id），插件不自建设置界面；API Key 经宿主 `credentials` 服务解析引用，
  不硬编码、不缓存、不写进配置文档、不随响应出网。
- **工具注册**：通过官方 `tools` 服务向会话注册模型工具，由宿主统一管理工具的生命周期与权限控制。
- **用户交互**：复用官方 `ask_user_question`、`todo_write`、`send_message`、`list_agents` 等工具，
  不重复造轮子。

这些通道全部由上游提供，改名或删行的症状是"起不来"或"静默读不出"。因此每一条都登记在
[DSH 接口账本](reference/dsh-surface-ledger.md)里并配一支探针，`npm run check:dsh` 逐条核对
（现 24 条）。升级 DSH 前先跑它。
