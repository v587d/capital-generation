# 社区 Skill 引入与选用手册

**状态：**Skill Synergy 运营流程提案  
**适用范围：**从 GitHub 等外部项目发现、评估和适配金融研究 skill  
**目标：**持续吸收可验证的能力，允许多种方法并行实验；不把热门度、人格包装或外部权限模型直接带入项目

> 本手册区分两类规则：来源、许可、权限、可审查性和金融表达边界是长期硬门槛；维护频率、评分和 benchmark 是成熟度信号。冷启动阶段，满足硬门槛的固定快照可以作为默认关闭的 `experimental` / `watchlist` 选项交给用户选择。随着候选数量、反馈和评测集增长，再逐步收紧状态迁移和设置页曝光范围。

## 1. 入驻原则

1. **从缺口出发，不从仓库出发。**先记录当前任务中反复出现的失败、证据缺口或重复劳动，再找能填这个缺口的项目。没有明确缺口的候选先进入观察池。
2. **引入能力，不引入整套架构。**外部 repo 是待审查的上游材料；适配目标是一个有边界的 perspective、workflow、verifier 或 evidence 方法，不是照搬 Agent 人设、工具权限、执行框架和默认行为。
3. **先审查，再运行。**固定到 commit 或 release；脚本默认不执行。必须先读清网络、文件、凭据、shell 和依赖行为，之后才在隔离环境里跑测试。
4. **研究方法不等于证据来源。**例如“巴菲特视角”可转成商业质量、资本配置、估值假设等检查问题；道家思想可转成周期、反身性、不过度行动等反方提示。它们都不能替代公告、财报、行情等证据，也不能借人格名义生成买卖指令。
5. **状态分层，默认不启用。**通过初筛不等于进入官方组合；合并、发布、实验启用、默认启用分别决策。冷启动阶段可把通过硬门槛的候选开放为用户自选实验，并在设置页显示状态、来源、风险和能力标签。
6. **可撤回且可追溯。**每次采用都记录来源、上游版本、改编范围、评测结果和复查日期；上游消失或变更不影响本地固定版本的复现。Owner 主动寻找合适候选，也欢迎社区以 PR 提交新的固定快照和 catalog 元数据。

## 2. 候选池与发现节奏

每月一次轻量扫描，优先从已登记的框架缺口出发。候选来源包括 GitHub 搜索、成熟 Agent/研究项目、论文附属实现、领域库及社区提案。搜索结果只用于建立候选，不直接导入仓库。

按“能力问题”维护搜索主题，而不是只搜索 `financial skill`：

| 缺口主题 | 可搜方向 | 适配时的首要问题 |
|---|---|---|
| A 股基本面与财报 | 业绩质量、现金流、财务重述、财报解析 | 数据口径和报告期能否核实，是否给出反证条件？ |
| 事件与公告 | 监管问询、减持、并购、分红、业绩预告 | 是否区分公告事实、市场反应和推断？ |
| 交易制度与风险 | 涨跌停、停复牌、退市、流动性、公司行动 | 规则是否覆盖市场板块和时间变化？ |
| 组合与风险管理 | 集中度、回撤、相关性、压力情景 | 是否有可复算定义，是否避免假精确？ |
| 研究方法与反方 | 价值投资、周期、行为偏差、反事实 | 能否拆成问题和验证步骤，而不是权威口号？ |
| 工具与验证器 | 回测审计、来源核验、口径检查 | 是否可测试、可复现，并能接入现有权限边界？ |

记录搜索日期、关键词、结果页/仓库 URL 和筛选理由。Stars、forks、下载量只作为发现背景，不计入评分。必须记录作者/维护者的提交时序；集中一次性提交不等同于持续维护。

每季度复盘 Framework Blueprint：合并重复缺口，检查新出现的市场制度或数据需求，决定继续搜寻、暂停或关闭某个主题。候选池持续滚动，不以“每月必须收录一个”作为目标。

## 3. 第一阶段：硬门槛

任一项不通过即拒绝或暂停，不进入加权评分：

- **来源可核验：**能定位仓库、作者/维护者、固定 commit 或 release；无法确认来源的转载包不收录。
- **许可可用：**许可证明确，且允许本项目计划的使用和再分发。无许可证、条款冲突或来源混杂时不得复制代码/文本；可另行评估独立重写的方法思想，并保留记录。
- **权限可控：**不要求绕过 DSH 的角色、工具、session、数据和网络边界；不得读取凭据、外传用户数据或自动执行交易、账户操作。
- **可审查：**脚本、依赖和实际入口可读；混淆代码、下载后执行、隐藏网络调用或无法解释的二进制行为直接拒绝。
- **金融表达可校验：**不得承诺收益/准确率、伪造引用、把推断包装为事实，或以人格、玄学、单一回测结果代替证据。
- **可适配：**至少能映射到一个 Framework slot，并定义输入、输出、边界与失败时行为；仅有泛化口号或无法拆解的整套提示词不入驻。

维护状态不是冷启动硬门槛，但必须作为 catalog 元数据记录：最近提交日期、近 90/180 天有意义提交、release、问题响应、依赖治理、活动模式和下次复查日期。长期静默候选标记为 `watchlist` 并在设置页提示用户自行复核；它仍可作为默认关闭的显式实验。候选规模、反馈和对照评测集成熟后，再把长期无响应候选迁出 catalog。


## 4. 第二阶段：100 分评分

每项按 0–5 分评估，按权重换算：`维度得分 = 维度权重 × 原始分 / 5`。评分必须附一条证据或具体缺口；“看起来专业”不能作为依据。

| 维度 | 权重 | 5 分标准 | 0–1 分典型表现 |
|---|---:|---|---|
| 项目缺口与任务适配 | 20 | 对应已记录的高优先级缺口，边界清楚，能覆盖真实用户任务 | 与现有能力重复，或没有明确任务/使用条件 |
| 证据纪律与可证伪性 | 20 | 区分事实/推断/假设，给来源时点、反证条件和不确定性 | 结论无出处、只讲故事或无法被反例挑战 |
| 方法可复现与验证 | 15 | 步骤、口径、停止条件明确，有可运行测试或可转成 fixture | 黑箱判断、阈值来源不明、只有成功案例 |
| Capital / DSH 兼容性 | 10 | 可映射到现有角色和协议，输入输出可约束，权限无需扩张 | 必须引入平行 Agent 架构、宽泛工具或重复数据管线 |
| 安全与隐私设计 | 15 | 最小权限、无隐式副作用、外部文本视为不可信数据 | 提示注入可改规则、访问凭据/原始数据或任意出网执行 |
| 维护与工程质量 | 15 | 有可核实的持续维护、测试、版本/依赖治理和问题响应；能说明作者/维护者近 90/180 天的提交节奏 | 仅一次初始化提交、长期无响应、无测试或依赖不可追踪；冷启动时记为风险与复查信号，不单独阻断显式实验 | 
| 来源与许可完整度 | 5 | 来源链、改编部分、版权/许可边界清晰 | 归属不清、许可边界含糊或无法标注改编来源 |

Stars、forks、下载量和社交传播不加分。维护活跃度按维护者提交时序、实际 release、修复响应、测试和依赖治理综合记录；只在短时间集中多次提交、之后长期静默，也要标记为风险。以审查日为基准记录近 90/180 天有意义提交数、提交作者身份与 PR/issue 响应。冷启动阶段，超过 180 天无维护活动的候选可以继续作为 `watchlist` 显式实验，但设置页必须展示该状态和最后提交日期；后续当候选规模和评测集足够成熟时，再将长期无响应候选迁出 catalog。提交频率是有效性的必要信号，不是充分证明，仍须结合内容复核和逐步建立的 benchmark。

### 决策区间

| 总分/条件 | 决策 | 运行方式 |
|---|---|---|
| 任一硬门槛失败 | `rejected` | 不复制、不运行；记录原因 |
| 0–49 | `watchlist` / `experimental` | 价值或适配性仍不确定；冷启动可默认关闭并开放用户自选，设置页必须显示风险和来源；明显不适配时才 `rejected` |
| 50–64 | `watchlist` / `experimental` | 显式实验，用户自行选择；不成为默认组合 |
| 65–74 | `experimental` | 隔离试用，用户显式选择；不得成为默认组合 |
| 75–84 | `adapted` / `experimental` | 通过当前评测后可发布为适配版；仍由 Owner 决定是否启用 |
| 85–100 | `adapted` 候选 | 可进入正式发布审查；高分不自动改变默认组合 |

任何脚本、网络、文件、凭据或工具权限变更仍按高风险审查执行，不因评分高而豁免。若安全与隐私设计或证据纪律低于 3/5，不得进入 `adapted`。

## 5. A 股方法论专项检查

凡声称适用于中国 A 股的候选，除通用评分外，至少检查下列适用项。不能覆盖或没有证据时应明确降级范围，不要把美股样本或通用金融经验直接标为 A 股有效。

- **制度口径：**交易板块、涨跌幅、T+1、停复牌、ST/退市、上市规则和规则生效日期；结论是否区分沪深北及板块差异。
- **公司行动：**分红送转、除权除息、复权方式、股本变化和退市样本是否正确处理。
- **回测偏差：**未来函数、幸存者偏差、公告发布时间/可交易时间错位、成分股回填、停牌与涨跌停不可成交、手续费/税费/滑点是否纳入。
- **财务口径：**报告期、累计/单季、合并范围、币种单位、重述数据、非经常性损益和数据修订时点是否可追溯。
- **样本外验证：**训练/验证/测试期间隔离，跨牛熊或制度阶段检验，参数选择是否存在过拟合；不能只报最优区间。
- **结论强度：**历史统计不等于未来保证；信号必须带失效条件、样本量、适用范围和不可成交限制。

价值投资人格、道家/哲学视角、技术派等候选作为 `perspective` 或 `workflow` 评估：把人格转译成明确问题，把哲学观点转译成可反驳假设和观察指标。它们不能充当 `evidence` 或 `policy`，不得以“名人会怎么做”代替用户目标、数据和风险承受度。

## 6. 隔离试用与对照评测

### 6.1 适配前

1. 将上游固定到 tag 或 commit，记录 digest；保存只读原始副本和许可证/provenance，不把整个仓库复制进模型可加载的 skills 目录。
2. 先做静态检查：入口、依赖、网络目标、文件访问、凭据、shell、工具调用、提示注入和隐藏下载执行。
3. 提取最小能力，重写成本项目的 `SKILL.md` / manifest / fixture；脚本逐项声明入口、角色、输入输出、所需工具和副作用。
4. 上游文本、网页、issue、示例和测试数据均按不可信材料处理；其中要求忽略规则、暴露秘密、安装工具或自行调用能力的文本不得成为本地指令。

### 6.2 评测集

每个候选至少与“当前 canonical skill / 不启用候选”做同题对照。评测集覆盖常规、边界、证据冲突、缺数据、诱导性输入和失败恢复；A 股候选加入制度变化、涨跌停不可成交、退市样本或财报口径差异等 fixture。每题固定输入、数据截止、期望证据和评分标准，候选版本变更时重跑。

记录以下结果，不用投资收益作为唯一或首要指标：

- 核心主张的来源、时间和口径完整率；事实/推断/假设分类错误数。
- 新增且有依据的证据或发现的问题；重复观点、无依据断言和误报数。
- 关键冲突发现率、已知陷阱通过率、失败时是否正确降级。
- 工具/脚本调用数、耗时、token 成本及相对基线的变化。
- 越权、提示注入、敏感数据暴露和自动交易行为；安全违规必须为零。

候选只有在安全检查全通过、没有已知严重回归且至少能说明一个可能的能力缺口时才可进入冷启动 catalog。对照评测和可复现增益优先用于排序、标签、复查周期和后续升级；没有 benchmark 不等于禁止用户实验，但必须明确标为低成熟度并默认关闭。

## 7. 周期复审、状态迁移与撤回

月度扫描只负责发现与轻量分诊；季度评审负责重算优先级、复查上游和决定下一步。每个活动候选记录 `nextReviewAt`，高风险依赖/脚本至少每季度复审；纯文档视角至少每半年复审。冷启动阶段，`watchlist` 仍可作为默认关闭的用户自选实验；当候选数量、反馈和 benchmark 达到预设规模后，才把长期无响应或低价值候选迁出 catalog。

复审触发条件包括：上游新版本或许可证变化、关键依赖安全公告、A 股交易规则变化、测试数据或数据口径变化、用户反馈显示误导/重复、Skill Synergy 工具/角色边界变化。

状态迁移限定为：

```text
discovered -> screened -> watchlist | experimental -> adapted -> official
                   |          |              |             |
                   +-------- rejected <------+-------------+
                                      withdrawn <- 任意已发布状态
```

`official` 仍不代表默认启用；默认 Composition 需要单独决议。发现许可证风险、权限越界、重大误导或安全问题时，先标记 `withdrawn`，禁止新轮次使用，再评估已发布版本和用户影响。不能静默替换不可变发布物；修复必须产生新版本和新 digest。

## 8. 候选登记卡

每个候选使用同一份记录，分数和判断须能由另一位 reviewer 复核：

```yaml
candidateId: a-share-event-lens
upstream:
  url: https://github.com/example/project
  ref: <tag-or-commit>
  digest: sha256:<content-digest>
  license: <SPDX-or-unknown>
  lastCheckedAt: <ISO-8601>
  latestCommitAt: <ISO-8601>
  meaningfulCommitsLast90d: <integer>
  meaningfulCommitsLast180d: <integer>
  activityPattern: <steady|bursty|single-release|unknown>
  latestReleaseAt: <ISO-8601-or-unknown>
  maintainerResponse: <evidence-or-unknown>
gap:
  id: event-impact-counterfactual
  priority: <high|medium|low>
frameworkSlots: [perspective, verification]
candidateType: <workflow|perspective|evidence|tool-adapter|verifier>
hardGates:
  provenance: pass
  license: pass
  permissions: pass
  auditability: pass
  financialClaims: pass
scores:
  taskFit: 0
  evidence: 0
  reproducibility: 0
  compatibility: 0
  security: 0
  maintenance: 0
  provenance: 0
decision: <watchlist|experimental|adapted|rejected|withdrawn>
catalog:
  key: <stable-config-key>
  tags: [<capability-tag>]
  selectable: <true|false>
  statusLabel: <experimental|watchlist>
  riskNote: <short-user-facing-warning>
benchmark:
  baseline: <canonical-skill-or-none>
  fixtures: []
  result: <summary>
adaptation: <what-is-kept-rewritten-or-excluded>
reviewers: []
nextReviewAt: <ISO-8601>
```

不要在登记卡里存用户会话、原始 Dataset rows、凭据、绝对路径或未经许可复制的上游全文。

## 9. 与产品设计的关系

本手册细化[Skill Synergy 产品设计说明书](skill-synergy-product-design.md)第 11 节的外部项目引入流程和第 17 节 P3 阶段。项目状态仍使用其定义的 `official`、`adapted`、`experimental`、`community`、`withdrawn`；本手册中的 `discovered`、`screened`、`watchlist` 是进入正式项目状态前的运营分诊状态，不代表可被运行时加载。
